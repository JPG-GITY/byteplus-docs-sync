## 1. Headline capabilities

- Up to **30 s** per video, up to **50 reference assets** per request.
- Native generation in **10+ languages**.
- Task families: reference (subject / motion / 3D clay-model / style / audio / storyboard /
  keyframe), first-and-last-frame, editing (visual + audio), extension, one-click video,
  seamless transition.

## 2. Locked vs unlocked — the distinction 2.0 does not have

**Locked** = the input asset is placed on the output timeline, so the model adapts to it and
some output parameters cannot be set. **Unlocked** = the asset is only a semantic reference.

| Task | What locks | Prompt trigger required |
|---|---|---|
| **Editing** | ratio → `adaptive`; **duration → `-1`**; `output_format: mov` recommended | role = `reference_*` **AND** a trigger word: *edit video, add, insert, remove, delete, modify, replace, change to* |
| **First frame / first+last** | ratio → `adaptive`, matching the FIRST image | role = `first_frame` / `last_frame` |
| **Extension** | ratio → `adaptive`; duration user-set; `mov` recommended | role = `reference_*` **AND** a trigger: *extend forward, extend backward, continue, continue from, extend the story* |

Notes that matter:
- Editing output duration may differ from the input by **≤ ~0.3 s** (transition-frame handling).
  If the input was itself generated by 2.5, there is **no** difference.
- With several input videos, **the prompt decides** which one is edited/extended.
- Last frame with a different ratio from the first **gets stretched** — use matching ratios.

**Unlocked, and worth calling out:**
- **Storyboard** (multi-panel grid) → visuals are **NOT** strictly aligned; it is a high-level
  plot reference only. Simple line art recommended; fill the rest in via the prompt.
- **Keyframes** (separate images) → visuals **ARE** relatively strictly aligned. Duration user-set.

> The escape hatch, stated explicitly: role can be `reference_image` with the images *named in
> the prompt* as first/last frame. This does **NOT** lock the ratio, and the result is "similar
> to" the frames rather than exact. (This is the path Aisling uses to keep dialogue audio.)

## 3. Reference asset limits & recommendations

| | Limit | Recommended |
|---|---|---|
| Images | **30**, up to 4K | **1–8 subjects** (9–12 possible, less stable) |
| Videos | **10**, ≤ **30 s** combined | **1–5 subjects**, **5–10 s** each |
| Audio | **10**, ≤ **30 s** combined | only what is relevant |
| Storyboard panels | — | **≤ 15**, stick-figure / line art, **no text on the image** |
| Video editing source | — | **≤ 20 s**; **1–5** reference images (6–8 possible) |
| 3D clay-model | — | coarse, simple geometric primitives |

Multi-view: for **1–5 subjects** single- and multi-view both work. For **>5 subjects**,
single-view is more stable — split views into **separate images**, never a collage.

## 4. Prompt writing — basic

Structure, in order:

1. **Asset referencing (R2V)** — identify every image/video/audio by **upload order** and its
   purpose (subject / voice / action / scene).
2. **One-sentence summary** — subject + location + event + genre/style + camera movement.
3. **Detailed plot** — shot sequence **or** timeline. Timestamps or "Shot N" divide it; per
   segment describe visuals, camera movement, action, dialogue, sound.
   **Prefer positive descriptions.**
4. **Additional notes** — what stays constant across the whole piece (angle, movement,
   environment, sound, atmosphere).

### Multi-asset mapping (the single most important thing as assets grow)

- Number by **upload order** — `Image 1` / `Video 1` / `Audio 1` — and bind each in the TEXT.
- **Do not** rely on labels drawn inside the image ("John" written on a picture) — it reliably
  causes character confusion or duplication.
- List mappings one by one; use a list when there are many characters:
  *"Images 1-2 are Character 1 and correspond to Audio 1; Images 3-4 are Character 2 and
  correspond to Audio 2."*
- State **what** to take from each asset, and **which part** if partial:
  *"Refer to the action of casting the spell in Video 1 and the wrap-around camera movement in
  Video 2."* · *"Refer to Image 1 for lighting and filters."*
- When a reference is already accurate, **reference it and stop** — do not re-narrate it.

### Timestamps

- Unit is **1 integer second**. **2.0 does not respond to timestamps** (shot numbers only); 2.5 does.
- Keep the timeline **continuous** — `0-3s … 3-7s … 7-15s`, never `0-3s … 5-6s`.
- Too little plot in a window → the model improvises; too much → over-cutting or dropped beats.
- **Do not** use timestamps for frequency ("shake your head 3× per second").
- Point-in-time works (*"quick left transition at the 5-second mark"*); relative time works
  (*"after 3 seconds, everyone around him shakes their head"*).

### Negative control

Supported for **subtitles** (*"no subtitles"*) and, per channel, for **audio** — SFX, BGM and
dialogue separately (*"No BGM; generate only environmental sounds and action sounds"*, *"No audio"*).
Note the official storyboard example ALSO carries a `[Strictly exclude]` block for **style**
(monochrome, line art, plastic CG…), so a style exclusion list is legitimate in practice even
though the guidance says to prefer positive description.

## 5. Prompt writing — advanced

**Camera language.** Shot size, movement (push in / pull out / pan / track / follow / orbit /
dive / tilt / handheld shake) and angle can be written plainly. Named techniques work directly:
long take, Hitchcock/dolly zoom, aerial, FPV, bullet time, handheld, speed ramp. **Niche terms
need `[term + explanation]`** — *"Rack focus: the foreground trees blur while the background
character resolves."* For transitions state **both** trigger point and method.

**Action.** Prefer **general** descriptions ("several sets of high-knee raises and somersaults").
Detail only a few memorable actions; avoid repeating the same action.

**Expressions.** Descriptive sentences; reduce idioms.

**3D clay-model.** Say exactly which elements to take (camera movement, motion, lighting
changes). Map each model to its target subject. Still describe the intended output in detail.

**Multi-panel storyboards.** ≤15 panels. Line art, uncluttered, no text baked in. Storyboards
are **not** followed frame by frame and they constrain creative output. Three steps: state asset
mappings → write the story summary → describe the plot per panel, filling in what the panels do
not show (timestamps allowed).

**Keyframe reference — use this when strict alignment is required.** Input each frame as its own
image, in order, and open the prompt with:
> **"Use Images 1 to N in order as keyframes."**

## 6. Differences from Seedance 2.0

1. **Timestamps** — 2.0 ignores them (shot numbers only); 2.5 honours integer seconds.
2. **Multi-view subject images** — discouraged on 2.0, supported on 2.5.
3. **Aspect ratio** — 2.0 has 6 fixed ratios; 2.5 supports **any ratio in [0.4, 2.5]** driven by
   the input assets.
4. **V2V quality** — 2.5 supports **MOV** output, preserving colour/brightness/audio-visual
   consistency in extension and editing.

## 7. The official worked template (storyboard example, condensed)

The shape the guide itself demonstrates — worth mirroring:

```
Image 1: nine-panel storyboard — overall shot structure, sizes, camera rhythm.
Image 2: environment reference — composition, light, colour.
Image 3: Subject 1 appearance.   Image 4: Subject 2 appearance.

[Subject settings]      one paragraph per subject, each naming its image
[Overall style]         film stock, grain, grading, lens, frame, atmosphere
[Strictly exclude]      styles that must not appear
[Shot list] (9 shots, ~30 seconds)
Shot 1 (0-3s): <size, camera position, movement> <content>
...
Shot 3 (6-10s): Facial close-up. ... Dialogue (elderly woman): "Fly safe, my child."
```

Dialogue in the official example is written plainly as `Dialogue (<speaker>): "<line>"`.
(A different rendering of this guide also documents `{}` for dialogue, `()` for music, `<>` for
SFX and `【】` for subtitles — both forms appear in ByteDance material.)

## 8. What this implies for Aisling

- Aisling's per-shot approved board is a **single** frame, so it should be addressed as a
  **keyframe** ("Use Images N…M in order as keyframes"), not as a "storyboard reference" —
  storyboard mode explicitly does not align, keyframe mode does.
- A segment holding several shots should be written as a **continuous timestamped timeline**
  (2.5 honours seconds), not as the 2.0-era "Shot N" list.
- The reference manifest must follow **attachment/upload order** exactly — the guide is explicit
  that mis-numbered mapping causes character confusion and duplication.
- The 2.0-era prohibition block ("do not use it as a starting frame, do not inherit its
  composition/angle/colour") fights the guide's "prefer positive description"; keep exclusions
  for style and for subtitles/audio, and express roles positively.
- Character sheets are multi-view — **fine on 2.5**, discouraged on 2.0. With >5 subjects, split
  views into separate images.
